The Smart Deposit Address (SDA) interface in `@tetherto/wdk-wallet/protocols` defines how a provider exposes deposit routes, creates route-bound deposit addresses, and optionally reports their lifecycle and transfer status.

<Callout type="warning">
`@tetherto/wdk-wallet` provides the SDA interface and abstract base class, not a concrete SDA provider. The currently released `@tetherto/wdk` package does not expose SDA-specific orchestration. Instantiate a concrete provider directly according to that provider's documentation.
</Callout>

## Imports

```typescript
import {
  SdaProtocol,
  type ISdaProtocol,
  type SdaCreateDepositAddressOptions,
  type SdaDepositAddress,
  type SdaDepositOptions,
  type SdaDepositQuote,
  type SdaRecoveryOptions,
  type SdaRecoveryResult,
  type SdaRoute,
  type SdaRoutesOptions,
  type SdaTransfer,
  type SdaTransfersOptions
} from '@tetherto/wdk-wallet/protocols'

import {
  NoSuchElementError,
  UnsupportedOperationError,
  ValueError
} from '@tetherto/wdk-wallet'
```

A provider subclass of `SdaProtocol` may be constructed with a writable account, a read-only account, or no account. A bound account supplies the default `destinationAddress` for address creation.

## Provider Contract

A concrete provider that extends `SdaProtocol` must implement route discovery and address creation. The remaining methods have default implementations that throw `UnsupportedOperationError`.

| Method | Support | Purpose |
|--------|---------|---------|
| `getSupportedRoutes(options?)` | Required | List supported source chains, input tokens, destinations, and route metadata. |
| `createDepositAddress(options)` | Required | Create and, when the provider has an activation lifecycle, activate deposit addresses. |
| `quoteDeposit(options)` | Optional | Return a non-binding estimate for a deposit. |
| `deriveDepositAddress(options)` | Optional | Derive an address client-side without activating or monitoring it. |
| `getDepositAddress(id)` | Optional | Look up an address descriptor by its provider identifier. |
| `renewDepositAddress(id)` | Optional | Refresh a time-limited address activation. |
| `getTransfers(address, options?)` | Optional | List transfers observed for an address. |
| `getTransfersByRecipient(destinationChain, recipient, options?)` | Optional | List transfers routed to a destination recipient. |
| `getTransfer(id)` | Optional | Read one transfer's current status. |
| `recoverDepositAddress(options)` | Optional | Ask the provider to reindex a deposit by SDA identifier or address. |
| `disableDepositAddress(id)` | Optional | Stop a provider from accepting deposits at an address. |

Check provider capabilities before building a flow around an optional method. An `UnsupportedOperationError` is a capability result, not a transient network failure.

## Deposit Flow

1. Call `getSupportedRoutes()` and select an advertised source chain, input token, destination chain, and output asset.
2. If the provider supports it, call `quoteDeposit()` for a non-binding estimate. Treat `expiry` as quote metadata, not a delivery guarantee.
3. Call `createDepositAddress()` with the selected route. Set `destinationAddress` explicitly, or bind an account whose address should be used as the destination.
4. Present the returned descriptor and its limits to the depositor before funds are sent.
5. If supported, monitor with `getTransfers()`, `getTransfersByRecipient()`, or `getTransfer()`.
6. Use renew, recovery, or disable operations only when the provider implements the corresponding lifecycle.

<Callout type="warning">
Address creation does not itself transfer funds. Validate that the returned descriptor matches the intended source chains, tokens, destination chain, output asset, and recipient before displaying or funding an address.
</Callout>

`createDepositAddress()` returns one descriptor per distinct address. A provider that uses one address across a chain family can return one descriptor covering every requested source chain; a provider that issues one address per chain returns multiple descriptors.

## Core Types

### Routes and tokens

```typescript
type Blockchain = string | number

type SdaRoutesOptions = {
  sourceChain?: Blockchain
  sourceToken?: string
  destinationChain?: Blockchain
  outputAsset?: string
}

type SdaToken = {
  token: string
  chain: Blockchain
  symbol: string
  decimals: number
  address?: string
  name?: string
}

type SdaRoute = {
  sourceChains: Blockchain[]
  inputTokens: SdaToken[]
  destinationChain: Blockchain
  outputAsset?: SdaToken
  limits?: {
    min?: number | bigint
    max?: number | bigint
  }
  reusable?: boolean
  estimatedDuration?: number
}
```

Route limits are denominated in the input token's base unit. A provider that only has limits in another denomination omits `limits` instead of converting them.

### Quotes

```typescript
type SdaDepositOptions = {
  sourceChain: Blockchain
  inputToken: string
  destinationChain: Blockchain
  outputAsset?: string
  inputAmount: number | bigint
}

type SdaDepositQuote = {
  inputChain: Blockchain
  inputToken: string
  inputAmount: bigint
  destinationChain: Blockchain
  outputAsset: string
  outputAmount: bigint
  fees: Array<{
    type: 'network' | 'protocol' | 'affiliate' | 'other'
    amount: bigint
    token: string
    chain?: Blockchain
    included?: boolean
    description?: string
  }>
  rate?: string
  expiry?: number
  id?: string
}
```

Quote amounts and itemized fees use base units. `rate` is a string to avoid precision loss, and the quote is non-binding.

### Deposit addresses

```typescript
type SdaCreateDepositAddressOptions = {
  sourceChains: Blockchain[]
  destinationChain: Blockchain
  outputAsset?: string
  destinationAddress?: string
}

type SdaDepositAddress = {
  address: string
  id: string
  sourceChains: Blockchain[]
  supportedInputTokens: SdaToken[]
  destinationChain: Blockchain
  outputAsset?: SdaToken
  destinationAddress: string
  limits?: {
    min?: number | bigint
    max?: number | bigint
  }
  reusable: boolean
  expiry?: number
}
```

Omitting `destinationAddress` uses the bound account's address. If no account is bound, the provider contract throws `ValueError`.

`deriveDepositAddress()` uses the same options but only computes an address client-side. It does not activate the address or cause the provider to monitor it.

### Transfer status

```typescript
type SdaTransferStatus =
  | 'pending'
  | 'detected'
  | 'processing'
  | 'completed'
  | 'failed'
  | 'refund-pending'
  | 'refunded'
  | 'expired'

type SdaTransfersOptions = {
  sourceChain?: Blockchain
  limit?: number
  skip?: number
  status?: SdaTransferStatus
}

type SdaTransfer = {
  id: string
  status: SdaTransferStatus
}
```

The base contract guarantees only an identifier and status for a transfer. Provider-specific implementations may expose more data, but portable integrations should not require amounts, hashes, or timestamps that are absent from `SdaTransfer`.

`sourceChain` can be required by a provider that keys an address by its address-and-chain pair. `limit`, `skip`, and `status` provide optional history pagination and filtering.

### Recovery

```typescript
type SdaRecoveryOptions =
  | { id: string }
  | {
      address: string
      sourceChain?: Blockchain
    }

type SdaRecoveryResult = {
  status: 'reindexed' | 'pending' | 'failed'
  address?: string
  id?: string
  transfer?: SdaTransfer
  message?: string
}
```

Recover by the `SdaDepositAddress.id`, or by address plus `sourceChain` when the provider requires chain context. A recovery result reports whether reindexing completed, remains pending, or failed; a recovered transfer is optional.

## Errors and Capability Checks

| Error | Meaning |
|-------|---------|
| `UnsupportedOperationError` | The provider does not implement an optional operation. |
| `ValueError` | Required route data is missing or invalid, or `destinationAddress` was omitted without a bound account. |
| `NoSuchElementError` | A requested address or transfer does not exist. |

Provider documentation remains authoritative for supported routes, activation windows, monitoring behavior, recovery semantics, and any additional option fields.
